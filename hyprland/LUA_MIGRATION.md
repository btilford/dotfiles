# Hyprland Lua Configuration Migration

## Overview

This document describes the migration from Hyprland's legacy `.conf` format to the new Lua API.

## Versions

- **Hyprland**: v0.55.0 (with Lua API support)
- **Lua API**: v0.55.0 (new in this version)
- **Migration Date**: 2025-05-13
- **Branch**: `hyprland-lua`
- **Base Branch**: `hyprland` (working `.conf` configuration)
- **Wallust**: Template updated to generate `colors-hyprland.lua`

## Migration Status

### Completed

All core configuration has been migrated from `.conf` files to `.lua` modules:

- **Entry point**: `~/.config/hypr/hyprland.lua`
- **Modules**: All configs live in `~/.config/hypr/lua/`:
  - `monitors.lua` — Monitor descriptions, positions, transforms, scales
  - `workspaces.lua` — Workspace rules using `hl.workspace_rule()`
  - `animations.lua` — Bezier curves and animation definitions
  - `windowrules.lua` — Window and layer rules
  - `keybindings.lua` — All key bindings (see Known Issues)
  - `autostart.lua` — Startup applications (non-blocking)
  - `environments.lua` — Environment variables
  - `decorations.lua` — Decoration settings
  - `keyboard.lua` — Keyboard configuration
  - `windows.lua` — Window behavior settings
  - `misc.lua` — Miscellaneous settings
  - `layouts.lua` — Layout configuration
  - `custom.lua` — Custom settings (SDL_VIDEODRIVER)
  - `colors.lua` — Generated by wallust

### What Changed

1. **Monitors** (`lua/monitors.lua`)
   - Left monitor: `transform = 1` (90° clockwise)
   - Right monitor: `transform = 3` (90° counter-clockwise)
   - XPPen: Positioned below center monitor at `0x1740`
   - All scales set to 1.5 for 4K displays

2. **Workspaces** (`lua/workspaces.lua`)
   - Rewritten from string format to `hl.workspace_rule()` API
   - 10 workspaces with monitor assignments and names
   - Uses `default_name` (snake_case) instead of `defaultName`

3. **Window Rules** (`lua/windowrules.lua`)
   - `rounding` reduced from 50 to 20 (API maximum)
   - Removed invalid `no_border` field (not supported in window rules)
   - Uses `hl.window_rule()` and `hl.layer_rule()`

4. **Animations** (`lua/animations.lua`)
   - Added `bezier = "liner"` to fade animation (required field)
   - Uses `hl.curve()` and `hl.animation()` API

5. **Autostart** (`lua/autostart.lua`)
   - All blocking `os.execute()` calls replaced with `hl.exec_cmd()`
   - 20+ startup applications launch non-blocking

6. **Wlogout** (`~/.config/wlogout/layout`)
   - Updated exit command to `hyprctl dispatch 'hl.dsp.exit()'`
   - Required for new Lua API dispatcher format

## Known Issues

### 1. Super_L / Super_R Modifier Distinction (Upstream Bug)

**Status**: ⚠️ Not supported in Lua API

**Impact**: Left and right Super keys cannot have different bindings. Both keys do the same thing.

**Root Cause**: Hyprland Discussion #11014 — the `s` flag (separate/sym) for `bind` has been broken for over a year. The Lua API doesn't expose left/right modifier distinction because the underlying compositor feature is broken.

**Workaround**: All bindings use generic `SUPER` modifier. Both left and right Super keys trigger the same actions.

**Original Behavior Lost**:
- Left Super (`Super_L`) was used for window management
- Right Super (`Super_R`) was used for workspace switching
- This separation is not possible in the Lua API

**Workaround Keybindings**:
- `SUPER + h/j/k/l` = move focus (was `Super_L`)
- `SUPER + CTRL + h/j/k/l` = move window (was `Super_L + CTRL`)
- `SUPER + SHIFT + h/j/k/l` = resize (was `Super_L + SHIFT`)
- `SUPER + 1-0` = workspace switching (was `Super_R`)
- `SUPER + Tab` = workspace cycling (was `Super_R`)

**When Fixed**: If Hyprland fixes Discussion #11014, the commented-out `Super_L`/`Super_R` keybinds in `keybindings.lua` can be uncommented and the generic `SUPER` bindings removed.

## Keybinding Changes for Window Management Priority

**Date**: 2025-05-13

To avoid conflicts between window management and workspace switching (since Super_L/Super_R distinction is broken), workspace commands have been moved to `SUPER + ALT` modifier combinations. This keeps simple `SUPER` keybinds free for window management.

### Changes from Original Config

**Application binds (changed from Super_L to SUPER)**
- `Super_L + RETURN` → `SUPER + RETURN` (open ghostty)
- `Super_L + B` → `SUPER + B` (open brave)
- `Super_L + CTRL + E` → `SUPER + CTRL + E` (open smile)
- `Super_L + CTRL + C` → `SUPER + CTRL + C` (open speedcrunch)

**Window Management (SUPER - Primary, easy to reach)**
- `SUPER + h/j/k/l` = Move focus (directional)
- `SUPER + CTRL + h/j/k/l` = Move window (directional)
- `SUPER + SHIFT + h/j/k/l` = Resize window (directional)
- `SUPER + Q` = Kill window
- `SUPER + F` = Fullscreen
- `SUPER + M` = Maximize
- `SUPER + T` = Toggle float + center
- `SUPER + C` = Center window

**Workspace Management (SUPER + ALT - Secondary, harder to reach)**
- `SUPER + 1-0` = Switch to workspace 1-10 (was `Super_R + 1-0`)
- `SUPER + Tab` = Next workspace (was `Super_R + Tab`)
- `SUPER + SHIFT + Tab` = Previous workspace (was `Super_R + SHIFT + Tab`)
- `SUPER + ALT + x/c/v/s/d/f/w/e/r/b` = Move window to workspace 1-10 (was `Super_R + CTRL + letter`)

**Mouse (unchanged)**
- `SUPER + mouse_down/up` = Next/previous workspace
- `SUPER + CTRL + down` = Next empty workspace

### How to Revert (when Super_L/Super_R is fixed)

When Hyprland fixes Discussion #11014, revert these changes:

1. **Application binds**: Change `SUPER` back to `Super_L` for consistency
2. **Window management**: Keep on `SUPER` (was `Super_L`)
3. **Workspace management**: Move back to `Super_R` (remove `ALT` modifier)
   - `SUPER + 1-0` → `Super_R + 1-0`
   - `SUPER + Tab` → `Super_R + Tab`
   - `SUPER + ALT + letter` → `Super_R + CTRL + letter`
4. **Remove duplicate SUPER bindings** for workspace switching

### Rationale

Since both left and right Super keys trigger the same actions, accidental workspace switches during window management were disruptive. By requiring `ALT` as an additional modifier for workspace operations, the simple `SUPER` key remains dedicated to window management, reducing accidental workspace changes.

### 3. Waybar Workspace 11 Ghost Display (Unresolved)

**Status**: ❌ Unresolved - upstream issue

**Problem**: Workspace 11 persistently appears on the XPPen monitor in waybar despite:
- Not being defined in `workspaces.lua`
- `hyprctl workspaces` showing workspace 11 does not exist
- `ignore_workspaces: [11]` set in all waybar modules
- Empty workspace creation keybind commented out

**Root Cause**: Waybar's `hyprland/workspaces` module creates ghost workspace entries when the persistent-workspaces configuration conflicts with workspace monitor assignments. This appears to be an interaction issue between:
- Hyprland Lua API workspace definitions
- Waybar's workspace display logic
- The `persistent-workspaces` vs `all-outputs` configuration

**Attempted Fixes**:
1. ✅ Added workspace 11 to `ignore_workspaces` in all waybar modules
2. ✅ Removed `persistent-workspaces` section from waybar config
3. ✅ Commented out `SUPER + CTRL + down` keybind that creates empty workspaces
4. ✅ Fixed monitor descriptions in workspaces.lua

**None resolved the issue.**

**Workaround**: None available. Workspace 11 can be ignored visually or waybar can be configured to not show workspace numbers.

**When Fixed**: Requires upstream investigation from either Hyprland or Waybar maintainers.

### 6. Glow Effect Implementation

**Status**: ✅ Implemented

**Implementation**: Replaced shadow with the new glow effect from Hyprland v0.55:

```lua
glow = {
    enabled = true,
    range = 12,
    render_power = 2,
    color = glow_color(colors.color15, "AA"),
    color_inactive = glow_color(colors.color0, "22"),
},
```

**Features**:
- Dynamic colors from wallust theme (uses `colors.color15` and `colors.color0`)
- Smaller radius (12) compared to default shadow
- Active windows get lightest color, inactive get subtle dark glow
- Automatically updates when wallust regenerates colors

### 7. jq JSON Parse Error in Wallpaper Script

**Status**: ⚠️ Documented - Non-fatal error

**Error Message**:
```
++ CURRENT_WALLPAPER=$(echo "$CURRENT_WALLPAPER" | jq -r .wallpaper)
jq: parse error: Invalid numeric literal at line 1, column 9
```

**Root Cause**: The jq error comes from a script called by `WallustSwww.sh` (likely `RefreshNoWaybar.sh`), not from the dotfiles scripts themselves. The error occurs when trying to parse wallpaper JSON that may be empty or malformed.

**Impact**: Non-fatal - the wallpaper script continues execution despite the error. Wallpapers still change, but with an error message.

**Fix Needed**: The `RefreshNoWaybar.sh` script (or other called scripts) needs error handling for jq parsing:
```bash
# Add error handling:
CURRENT_WALLPAPER=$(echo "$CURRENT_WALLPAPER" | jq -r .wallpaper 2>/dev/null || echo "")
```

**Workaround**: The error can be safely ignored. Wallpapers still change automatically.
